# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project shape

A typed Next.js app (App Router, TypeScript strict) with two views over the same todo data:

- `app/list/` — list view with filters, search, stats, add form, edit dialog.
- `app/board/` — pan/zoom infinite-canvas board grouped by tag.

Both pages are RSC entry points that fetch todos via `listTodos()` and hand them to a `'use client'` view component (`components/list-view.tsx`, `components/board-view.tsx`). After mutations, the client view re-fetches via `GET /api/todos` and calls `router.refresh()` to invalidate the server cache.

A predecessor branch stored todos in `localStorage["filip_todos"]`. `components/import-banner.tsx` detects that key on first load and offers a one-time import to `/api/todos/import`.

## Data + validation boundary

`lib/schema.ts` is the single source of truth for `Status` and `TodoInput` types — both are `z.infer<>` of the Zod schemas. Route handlers go through `parseJsonBody(req, schema)` from `lib/api.ts`, which returns either `{ ok: true, data }` (with the schema's *output* type) or `{ ok: false, response }` containing a 400 with `error: "Invalid"` and `issues`.

Don't add a separate TS type for todo inputs — extend the Zod schema and re-infer. Likewise, don't validate inline in a route handler.

## DB layer

`lib/db.ts` uses raw SQL via `@vercel/postgres`'s tagged-template `sql`. There is no ORM and no client singleton (the package manages pooling internally). Schema lives in two places — `ensureSchema()` and `scripts/init-db.mjs` — and **both must be updated together** when adding columns.

The schema mirrors `gift-list/lib/db.ts` deliberately. If you change the pattern here (e.g. swap to `@neondatabase/serverless`), update the README's "Notes" section that points at gift-list.

## Auth

Admin-only, single account. `lib/auth.ts` signs an HS256 JWT and stores it in a cookie (`todo_admin_session`). `middleware.ts` is the *only* gate — route handlers do not call `getSession()` themselves. The middleware exempts `/login`, `/api/auth/login`, `/api/auth/logout`, and Next's static assets. Anything else without a valid session is redirected (for pages) or returns a 401 JSON response (for API routes).

`AUTH_SECRET` must be at least 16 chars; `getSecret()` throws otherwise — which is how unit tests assert the failure path.

## Board view internals

The pan/zoom state lives in a `useRef({ tx, ty, scale })`; only `zoomLabel` is in React state. Mutating the ref + calling `applyTransform()` writes `canvas.style.transform` imperatively — putting `tx`/`ty` in React state would force a re-render of every card on every pixel of drag. The fixed-header chips above the canvas are repositioned by `updateHeaderPositions()` on the same tick. Wheel handler distinguishes pinch (browser sets `ctrlKey: true` on a trackpad pinch) from two-finger pan.

The empty `<span data-i={i}>` inside each chip is intentional — it keeps a per-chip index attribute available for debugging without changing the visible markup.

## Conventions

- shadcn primitives live in `components/ui/` and were copied (not generated by the CLI); when adding new ones, prefer the same style with `cn()` + `cva` so they slot in.
- Use existing `Status` / `TodoInput` / `Todo` types from `lib/schema.ts` and `lib/types.ts` rather than redefining shapes.
- Tag colours come from `lib/tag-colors.ts` (`hashStr` + golden-angle HSL spread) — that's the single source.
- Deadlines come from `lib/deadline.ts` (`deadlineStatus`, `fmtDeadline`).
- Unit tests live next to nothing — they're all in `tests/unit/`. Integration tests in `tests/integration/` invoke route handlers directly with native `Request` objects and skip cleanly when `POSTGRES_URL` isn't set (`describeWithDb` from `tests/integration/helpers/db.ts`).
